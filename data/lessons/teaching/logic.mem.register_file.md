# Register files and ports

A register file is a small, fast, heavily multi-ported memory: a processor reads two operands and writes one result per instruction, and a superscalar core does that for several instructions per cycle. Ports, not bits, dominate its cost. Register files are generated by memory compilers or built from flip-flops and muxes by synthesis, and choosing between the two is a recurring physical-design decision.

## Ports from the instruction mix

Each instruction of a typical RISC machine reads up to two source registers and writes one destination. A core that issues $w$ instructions per cycle needs $2w$ read ports and $w$ write ports to avoid structural conflicts. A 4-wide core needs 8 read and 4 write ports, 12 in all.

Each read port has its own address decoder and output mux; each write port has its own decoder and write drivers. With $R$ registers, every port takes a $\log_2 R$-bit address: a 64-entry, 12-port file decodes $12 \times 6 = 72$ address bits every cycle. Designers cut port counts with banking, port sharing or clustering of the execution units, accepting occasional stalls.

## Why area grows quadratically

In a multi-ported cell, each port adds a wordline (running horizontally) and at least one bitline (running vertically). If a cell needs a base of $a$ wire tracks in each direction plus one per port, its side grows as $a + p$ and its area as $(a + p)^2$.

With $a = 2$, going from 3 ports to 12 ports multiplies cell area by $(14/5)^2 = 7.84$. The longer wires also slow every access, so a heavily ported file is both large and slow. This is the physical reason wide superscalar cores split their register files, and why synthesis of a large many-ported register file from flip-flops quickly becomes routing-dominated.

## Write-before-read and bypassing

A register file written and read in the same cycle needs a rule. A common one is to write in the first half of the cycle and read in the second, so an instruction reading a register sees a value written by an instruction three stages ahead in the same cycle. That timing trick is what lets the classic five-stage pipeline avoid one stall cycle.

Values produced but not yet written are delivered by bypass (forwarding) paths that route an ALU result straight to the next instruction's inputs, around the register file. With issue width $w$ and $k$ bypassed stages, each operand mux chooses among roughly $1 + w k$ sources, and the bypass network, not the file itself, often becomes the critical path. Microarchitecture, register-file design and timing closure meet here.
