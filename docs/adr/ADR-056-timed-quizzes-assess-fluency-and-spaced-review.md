# ADR-056: A timed quiz assesses fluency; spaced review owns the FSRS schedule

*2026-10-28*

**A timed quiz is a fourth assessment surface, not a second mastery check.** The 50 XP mastery check stays exactly as ADR-046 left it: a short, ungated-by-score run that admits a learner after enough XP since the last completion. The timed quiz is separate. It becomes due after 150 positive XP earned after a durable rollout baseline, it samples concepts the learner has already studied, including mastered concepts, and it runs against a server-owned ten-minute deadline. The two gates never read each other. Changing `QuizGateXP` would have made one number describe two different questions, and a learner who is due for a fluency check is not necessarily due for a mastery check.

**The baseline exists because lifetime XP is not a rollout schedule.** A migration writes one `timed_quiz_baselines` row per existing student at the moment of deployment, holding `xp_total` and the rollout timestamp. New accounts get a zero baseline when they are created. Eligibility sums only positive `xp_events.amount` at or after the baseline, so a historical total cannot make every existing learner eligible at once and a later penalty cannot take earned XP back below the gate. A completed timed run moves the effective start to its `completed_at`, so the run consumes its gate exactly once. The sum is from the ledger, not `xp_total - baseline_xp`, because the ledger is the durable record of what was earned.

**A timed quiz produces mastery evidence and XP, and nothing else.** Answers use the existing grader, evidence window, mastery ladder and XP policy. They do not update FSRS stability, difficulty, `FSRSLastReview`, `LastReviewed` or `NextReviewDue`, and they create no `review_events` row. The change that makes this true is a `review` flag on `gradedAttempt`: `SubmitAnswer` sets it only when the active session is a spaced review, and every practice, mastery-check and timed-quiz path sets it false. The FSRS block runs when `review` is true or when a concept first reaches MASTERED. The first-mastery branch is initialization, not an advance: without it a newly mastered concept could never enter the review queue. A practice or quiz miss no longer sets `NextReviewDue = now`; only a missed review does that.

**Review is the only writer, and it writes an event.** A spaced-review answer is still an ordinary `attempts` row, but it now also records one `review_events` row keyed by `sessionID:attemptID`. The row stores the rating, correctness, elapsed time, the before and after stability and difficulty and the before and after due date. The unique attempt key makes a replay idempotent: the insert uses `ON CONFLICT DO NOTHING`, so a retried submission cannot produce a second scheduler update. Historical review attempts are not backfilled. The old rows did not store a rating or the before and after state, and inventing them would be a fabricated history. The rating remains objective: Good for a correct answer and Again for an incorrect one. Hard and Easy are not inferred from response time, because a faster answer is not the same claim as a recalled one.

**Durability is the difference between a timed quiz and the mastery check.** Mastery-check sessions remain in server memory, where a restart means a retake. A timed quiz is a `timed_quiz_runs` row with `timed_quiz_items`, so a reload resumes the same questions and the same deadline, and a restart does not refund time. The partial unique index on `(student_id) WHERE status = 'active'` prevents two concurrent starts. An item is claimed before it is graded, with a conditional update from `served` to `submitting`; only the request holding that claim may write the attempt. The answer itself goes through `answer_submissions` with operation `timed_quiz`, which stores the response and the attempt in one transaction. A lost response replays the stored result instead of awarding a second attempt. Finalization is a conditional update from `active` to `completed`, so repeated finalize calls return the same row. The deadline is checked before the claim, and a late answer finalizes the run and returns its result rather than grading.

**The review queue did not grow a second source of truth.** `buildCandidates`, `DueReviewCount` and `NextReview` still share one builder. Only stored MASTERED concepts enter it, and an unassessed or LEARNING concept is not labeled forgotten. The timed quiz has its own candidate rule because it samples learned material, including mastered material, but it still requires a graded attempt and satisfied prerequisites. Neither surface invents a second scheduler.

**What is deliberately absent.** The timed quiz does not have a PASS/FAIL verdict. It reports a score, per-item feedback, unanswered items and remediation links, but no threshold turns that score into a mastery or review decision. The review queue has no separate first-review onboarding policy; the first review is still scheduled when a concept reaches MASTERED. FSRS remains pinned to `fsrs==6.3.2`, retention 0.90 and a 36,500-day maximum interval. FIRe stays shadow-only. The build does not mass-seed FSRS from SM-2 and does not recalculate historical schedules.
